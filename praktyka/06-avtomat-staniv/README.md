2. Намалювати **діаграму станів**: прямокутники — стани, стрілки —

Файли: `dijagrama.png` (можна фото від руки), `misiya.py`,
`video.mp4` або посилання, `zvit.md`.

## Каркас — робочий, від нього можна відштовхнутись

Робот їде до перешкоди, сповільнюється, зупиняється й розвертається.
У світі Grid працює як є. Замініть стани й умови на свою місію.

```python
from ev3dev2.motor import MoveTank, OUTPUT_A, OUTPUT_B, SpeedPercent
from ev3dev2.sensor import INPUT_2, INPUT_3
from ev3dev2.sensor.lego import UltrasonicSensor, GyroSensor
import time

tank = MoveTank(OUTPUT_A, OUTPUT_B)
ultra = UltrasonicSensor(INPUT_2)     # ⚠️ у Gears порт обов'язковий
gyro = GyroSensor(INPUT_3)
time.sleep(0.5)

stan = "poshuk"
vkhid = time.time()                   # коли увійшли в поточний стан


def perekhid(novyi):
    """Єдине місце, де змінюється стан: друк і дії при вході."""
    global stan, vkhid
    print(f"{stan} -> {novyi}")
    stan = novyi
    vkhid = time.time()
    if novyi == "rozvorot":
        gyro.reset()                  # скинути гіроскоп при вході в поворот


while stan != "gotovo":
    d = ultra.distance_centimeters

    if stan == "poshuk":              # їдемо вперед, дивимось уперед
        tank.on(SpeedPercent(30), SpeedPercent(30))
        if d < 45:
            perekhid("pidhid")

    elif stan == "pidhid":            # наближаємось повільно
        tank.on(SpeedPercent(10), SpeedPercent(10))
        if d < 15:
            perekhid("rozvorot")

    elif stan == "rozvorot":          # розвертаємось на місці
        tank.on(SpeedPercent(20), SpeedPercent(-20))
        if gyro.angle >= 180:
            tank.off()
            perekhid("gotovo")

    if time.time() - vkhid > 20:      # таймаут: стан без виходу
        print("таймаут у стані", stan)
        tank.off()
        break
```

✔ У консолі три рядки: `poshuk -> pidhid`, `pidhid -> rozvorot`,
`rozvorot -> gotovo`.

⭐ Зверніть увагу: **у кожен момент робот перебуває рівно в одному
стані**, стан змінюється тільки в `perekhid()`, і в коді немає жодного
вкладеного `if` глибше двох рівнів. У цьому вся ідея.

## Якщо щось пішло не так

| Що бачите | Причина | Що зробити |
|---|---|---|
| `TypeError: No ultrasonic sensor connected to null` | датчик без порту | `UltrasonicSensor(INPUT_2)`, `GyroSensor(INPUT_3)` |
| останній рядок у консолі — `poshuk -> pidhid`, і більше нічого | застряг у стані: умова переходу не виконується | подивитись на умову цього стану; для того й друк |
| `таймаут у стані …` | стан без виходу | це не помилка таймауту — це він вас урятував; виправити умову |
| розворот не закінчується | гіроскоп не скинули або крутиться ліворуч (кут від'ємний) | `gyro.reset()` при вході; швидкості `20, -20` |
| стан міняється щоцикла туди-сюди | умова на межі — тремтіння | гістерезис із роботи 4: два пороги |
| сцена не завантажується | файл не з World Builder | Worlds → World Builder → File → Save world to file |

## ⭐ Головне сьогодні

«Одна велика функція з `if`» ламається на четвертій умові. Не тому,
що ви погано пишете — тому, що умови починають перетинатись,
і ви більше не можете сказати, у якому стані робот зараз.

Автомат станів прибирає саме це: **завжди зрозуміло, де ви є
й куди можете піти далі.**

## Три рівні

**Ядро (всі).** Діаграма намальована, 3–4 стани працюють, переходи
друкуються, є таймаут, відео знято.

**Трек Д.** Діаграма має бути зрозуміла **людині без технічної
освіти**: назви станів словами, а не `stan_2`; підписані переходи.
Плюс подумайте, як робот **показує назовні**, у якому він стані —
рух, пауза, розворот. Це поведінка як комунікація.

**Трек П.** Додати **стан обробки відмови**: робот застряг —
відʼїхати назад, повернути, спробувати ще раз. Порахувати
на десяти прогонах, скільки разів цей стан спрацював.
