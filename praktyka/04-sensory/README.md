## Умова

Зняти реальні покази датчика й знайти **поріг спрацювання
для своєї сцени**.

1. Обрати датчик під свою місію: лінії, ультразвуковий або гіроскоп.
2. Обрати світ для замірів: датчик лінії — **Worlds → Select World →
   Line Following Challenges** (траса *Simple Curves*, робот стартує
   просто на лінії); ультразвук — світ **Grid** (по краях поля стіни).
3. Написати програму, яка їде й **друкує покази** кожні пів секунди
   (каркас нижче).
4. Провести робота через різні ділянки: світле, темне, межу, близько
   до стіни, далеко, під кутом до стіни.
5. Зібрати не менше **20 показів** у таблицю.
6. Побудувати графік — хоч у таблиці, хоч від руки, хоч у Excel.
7. Обрати **поріг** і записати, чому саме це число.

Файли: `pokazy.md` (таблиця + графік), `zvit.md` (обраний поріг
і обґрунтування).

<details>
<summary>Каркас: їхати й друкувати покази</summary>

```python
from ev3dev2.motor import MoveTank, OUTPUT_A, OUTPUT_B, SpeedPercent
from ev3dev2.sensor import INPUT_1, INPUT_2
from ev3dev2.sensor.lego import ColorSensor, UltrasonicSensor
import time

tank = MoveTank(OUTPUT_A, OUTPUT_B)
color = ColorSensor(INPUT_1)          # ⚠️ у Gears порт обов'язковий
ultra = UltrasonicSensor(INPUT_2)
time.sleep(0.5)

tank.on(SpeedPercent(10), SpeedPercent(10))
for i in range(1, 21):
    print(i, color.reflected_light_intensity, round(ultra.distance_centimeters, 1))
    time.sleep(0.5)
tank.off()
```

</details>

## ⚠️ Чим Gears відрізняється від справжнього датчика

| Що | У Gears | Що з цим робити |
|---|---|---|
| **шум** | немає: нерухомий датчик щоразу дає те саме число | заміри робити **в русі**; якщо потрібен шум — додати самим: `v = color.reflected_light_intensity + random.randint(-8, 8)` (і `import random`) |
| **біле поле траси** | не одне число, а цілий діапазон — залежить від того, куди повернутий робот | поріг не ставити впритул до білого |
| **ультразвук і коса стіна** | під великим кутом стіна «зникає» — датчик бачить щось далі | з якого кута — виміряйте (⭐ нижче) |
| **GPS** | точні координати | тільки для налагодження; місія через GPS не зараховується як автономна навігація |
| **порт** | обов'язковий | колір — `INPUT_1`, ультразвук — `INPUT_2`, гіроскоп — `INPUT_3` |

⭐ Ускладнення № 3 з матриці варіантів — «датчик шумить сильніше за
норму» — у Gears робиться саме так: шум додається в програмі.

## ⭐ Головне сьогодні

Датчик не повідомляє «тут лінія». Він повідомляє **число**.
Перетворити число на рішення — ваша робота, і саме тут з'являється
поріг.

І друге: **той самий датчик на різній поверхні дає різні числа.**
Тому поріг, підібраний на чужій сцені, на вашій не працює.

## Три рівні

**Ядро (всі).** Таблиця показів, графік, обраний поріг із поясненням.

**Трек Д.** Підібрати **контраст поверхонь** так, щоб датчик працював
надійно. Це задача про матеріал, колір і світло: наскільки різними
мають бути дві поверхні, щоб датчик їх упевнено розрізняв. Запишіть
знайдену межу числом.

**Трек П.** Зробити **гістерезис** — два пороги замість одного:
один для переходу «на лінію», інший для «з лінії». Поставити робота
на край лінії, **додати шум** (без нього в Gears перемикань може
не бути зовсім) і на тих самих 60 замірах порівняти, скільки разів
рішення перемикається при одному порозі і скільки при двох.

## ⭐ Із зірочкою

Знайти умови, за яких **ваш поріг ламається**: поверхню, напрямок
робота, швидкість — за яких датчик починає помилятись.
Для ультразвуку: під'їхати до стіни й повертати робота по 10°,
знайти кут, з якого стіна «зникає».

Запишіть їх. ⚠️ Це прямий матеріал для розділу «Аналіз відмов»
у курсовій — найдорожчого розділу записки.
